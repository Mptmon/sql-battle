# История изменений SQL Battle

## Текущая сессия разработки

### 🎨 ФРОНТЕНД — все изменения

#### 1. `lib/api.ts`

**Изменение 1.1:** Добавлен параметр `timeSpent` в функцию `submitSolution()`
- **Для чего:** Передавать на бэкенд время, которое пользователь фактически потратил на решение задачи
- **Почему:** В соревновании важно время размышлений участника, а не скорость работы сервера. Время выполнения БД зависит от нагрузки и не отражает навыки

**Изменение 1.2:** Заменен `avgTime` на `totalTimeSpent` в `getLeaderboard()`
- **Для чего:** Лидерборд показывает суммарное время, затраченное на все решенные задачи
- **Почему:** Суммарное время — более справедливая метрика. Участник, решивший 5 задач за 2 минуты каждую (10 минут), должен быть выше того, кто решил 5 задач за 4 минуты (20 минут)

#### 2. `app/(arena)/lobby/page.tsx`

**Изменение 2.1:** Добавлен большой таймер обратного отсчёта "как на бомбе"
- **Для чего:** Участник видит время до начала турнира и не может начать раньше
- **Почему:** В честном соревновании все стартуют одновременно. Яркий таймер создает атмосферу и не дает начать раньше

**Изменение 2.2:** Кнопка "Приступить" активируется только после истечения таймера
- **Для чего:** Физически заблокировать переход к задачам до старта
- **Почему:** Защита от случайных кликов и понятный сигнал "ещё рано"

**Изменение 2.3:** Добавлены 4 состояния лобби (waiting → ready → completed → finished)
- **Для чего:** Разные экраны для разных этапов турнира
- **Почему:** Пользователь должен четко понимать, что происходит: ждёт старта / может начать / ждет окончания / может смотреть результаты

**Изменение 2.4:** Сохранение `tournament_start` и `tournament_end` в localStorage
- **Для чего:** Layout может проверять статус турнира без запросов к бэкенду
- **Почему:** Быстрее и надежнее, чем дергать API каждую секунду

**Изменение 2.5:** Установка флага `allTasksCompleted` при возврате после решения всех задач
- **Для чего:** Лобби знает, что пользователь закончил задачи, и показывает нужное состояние
- **Почему:** Без этого флага лобби не отличит "ещё не начинал" от "уже закончил"

**Изменение 2.6:** Заменены тестовые таймеры на разумные дефолты
- **Для чего:** Аварийный режим на случай, если бэкенд не отвечает
- **Почему:** Тестовые значения (10 сек / 60 сек) сломают логику в продакшене. Теперь по умолчанию турнир "уже начался" и закончится через 2 часа

#### 3. `app/(arena)/battle/page.tsx`

**Изменение 3.1:** Убран хардкод `CURRENT_TASK_ID = 3`
- **Для чего:** Страница не привязана к конкретной задаче
- **Почему:** В турнире каждому участнику назначается своя последовательность задач

**Изменение 3.2:** Динамическая загрузка через `getAssignedTask()` + `getTaskById()`
- **Для чего:** Получить ID назначенной задачи, затем её полное содержимое
- **Почему:** `getAssignedTask()` возвращает только базовую информацию, а для отображения нужны условие и схема

**Изменение 3.3:** Скрытие результата проверки от пользователя
- **Для чего:** Участник не знает, правильно ли решил задачу, до конца турнира
- **Почему:** Это ключевое правило честного соревнования. Иначе можно угадывать методом проб и ошибок

**Изменение 3.4:** Автопереход к следующей задаче после "Отправить решение"
- **Для чего:** Непрерывный конвейер задач без возврата в лобби
- **Почему:** Возврат в лобби тратит время, дает возможность подсмотреть результаты и прерывает концентрацию

**Изменение 3.5:** Сброс таймера на 5 минут при смене задачи
- **Для чего:** Каждая новая задача дает полный лимит времени
- **Почему:** Без сброса таймер продолжал бы тикать от предыдущей задачи

**Изменение 3.6:** Автоматический переход при истечении времени
- **Для чего:** Участник не застревает на задаче, которую не может решить
- **Почему:** Время ограничено, нужно двигаться дальше

**Изменение 3.7:** Экран "Загрузка следующей задачи..." с задержкой 1.5 сек
- **Для чего:** Плавный переход между задачами
- **Почему:** Мгновенная загрузка выглядит как "моргание", пользователь не успевает понять, что произошло

**Изменение 3.8:** Сброс флага `isTournamentActive` и установка `allTasksCompleted` при завершении
- **Для чего:** Корректное завершение турнира и возврат в обычное состояние
- **Почему:** Без сброса флагов навигация останется заблокированной навсегда

**Изменение 3.9:** Редактор SQL очищен от тестового запроса
- **Для чего:** Участник начинает с чистого листа
- **Почему:** Тестовый запрос может содержать подсказки или быть от другой задачи

**Изменение 3.10:** Защита от перехода на арену до начала турнира
- **Для чего:** Редирект в лобби, если турнир не активен
- **Почему:** Защита от ручного ввода URL `/battle` до старта

**Изменение 3.11:** Передача `timeSpent` при отправке решения
- **Для чего:** Отправлять на бэк время, затраченное на задачу
- **Почему:** Без этого бэкенд не сможет корректно считать статистику времени

### 🔧 Необходимые доработки на бэкенде (для Дани)

#### Часть 1: Критические исправления (5 файлов)

**1. `backend/auth.py` — Fallback для `SECRET_KEY`**
- **Для чего:** Избежать ошибок JWT, если переменная окружения не загрузилась
- **Почему:** Без fallback все JWT-операции упадут при первом запуске
- **Решение:**
```python
ACTIVE_SECRET_KEY = getattr(settings, 'SECRET_KEY', None) or "your-super-secret-key-change-in-production"
# Использовать ACTIVE_SECRET_KEY вместо settings.SECRET_KEY везде
```

**2. `backend/services/__init__.py` — Исправить `compare_results`**
- **Для чего:** Избежать `TypeError` при сравнении разнотипных данных
- **Почему:** SQL возвращает данные разных типов, Python падает при сортировке
- **Решение:** Сортировать по кортежу `(тип_данных, значение)`, а не по самим значениям

**3. `backend/routers/profile.py` — Добавить эндпоинты `/` и `/history`**
- **Для чего:** 
  - `@router.get("/")` — ловить запросы с косой чертой (исправляет 404)
  - `@router.get("/history")` — возвращать историю попыток с названиями задач
- **Почему:** 
  - FastAPI различает `/profile` и `/profile/` как разные пути
  - История попыток нужна для отображения в профиле

**4. `backend/routers/websocket.py` — Валидация токена из URL**
- **Для чего:** WebSocket принимает только авторизованных пользователей
- **Почему:** Без валидации любой может подключиться и получать данные
- **Решение:** Добавить параметр `token: str = Query(None)` и валидацию JWT через `jwt.decode`

**5. `backend/routers/leaderboard.py` — Привести `avg_time` к `float`**
- **Для чего:** Избежать ошибок при округлении
- **Почему:** SQLAlchemy возвращает `Decimal`, что вызывает проблемы при сериализации
- **Решение:**
```python
avg_time = round(float(avg_time_ms) / 1000, 2) if avg_time_ms else 0.0
```

#### Часть 2: Новая логика времени (4 изменения)

**6. Модель `Submission` — добавить поле `time_spent`**
- **Для чего:** Хранить время, потраченное пользователем на задачу
- **Почему:** Сейчас хранится только `execution_time_ms` (время БД), которое не отражает усилия участника
- **Решение:**
```python
time_spent = Column(Integer, nullable=True)  # время в секундах
```

**7. Эндпоинт `POST /tasks/{task_id}/submit` — принимать `time_spent`**
- **Для чего:** Записывать затраченное время в БД
- **Почему:** Фронтенд уже отправляет это поле, но бэкенд его игнорирует
- **Решение:** Добавить поле `time_spent: int` в Pydantic-схему и сохранить в БД

**8. Эндпоинт `GET /leaderboard` — заменить `func.avg` на `func.sum`**
- **Для чего:** Показывать суммарное время на правильно решенные задачи
- **Почему:** Среднее время БД не имеет смысла для ранжирования
- **Решение:**
```python
total_time_result = await db.execute(
    select(func.sum(Submission.time_spent)).where(
        Submission.user_id == user.id,
        Submission.is_correct == True,
        Submission.time_spent.isnot(None)
    )
)
total_time_spent = int(total_time_result.scalar() or 0)
```
В схеме `LeaderboardEntry` заменить поле `avg_time: float` на `total_time_spent: int`

**9. Эндпоинт `GET /profile/history` — добавить поле `time_spent`**
- **Для чего:** Фронтенд может отобразить время на каждую задачу
- **Почему:** Без этого поля профиль показывает `0м 00с`
- **Решение:**
```python
history.append({
    "id": sub.id,
    "task_title": title,
    "difficulty": difficulty,
    "is_correct": sub.is_correct,
    "points_earned": sub.points_earned,
    "time_spent": sub.time_spent or 0,  # НОВОЕ ПОЛЕ
    "created_at": sub.created_at.isoformat() if sub.created_at else ""
})
```

## 🧪 Тестирование

### Полный цикл тестирования

1. **Авторизация** → попадаешь в лобби
2. **Состояние 1 (waiting)**: Красный таймер, вкладки видны
3. **Состояние 2 (ready)**: Зеленая карточка "Турнир начался!", вкладки скрыты
4. Нажимаешь "ПРИСТУПИТЬ К РЕШЕНИЮ" → переходишь на арену
5. Решаешь задачи (или нажимаешь "Отправить" с пустым запросом)
6. Когда задачи закончатся → возвращаешься в лобби
7. **Состояние 3 (completed)**: Синяя карточка "Отличная работа!", вкладки скрыты
8. Ждешь окончания турнира
9. **Состояние 4 (finished)**: Желтая карточка "Турнир завершен!", вкладки видны
10. Нажимаешь "ОЗНАКОМИТЬСЯ С РЕЗУЛЬТАТАМИ" → переходишь на лидерборд

### Быстрое тестирование (без бэкенда)

Открой консоль браузера (F12) и выполни:
```javascript
// Установить старт через 3 секунды, конец через 10 секунд
localStorage.setItem("tournament_start", new Date(Date.now() + 3000).toISOString())
localStorage.setItem("tournament_end", new Date(Date.now() + 10000).toISOString())
location.reload()
```
